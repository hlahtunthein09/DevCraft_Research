# DevCraft Presentation Redesign — Final Codex Implementation Brief

## Purpose

Update the existing DevCraft presentation website based on the current:

- `index.html`
- `style.css`
- `script.js`

The current presentation already contains useful content, but it is not easy enough to understand as a live classroom presentation.

The main problem is not only visual quality.

The bigger problem is that the audience must mentally connect too many disconnected pieces themselves.

The redesign must make the logic obvious.

The final presentation must help both:

- the presenter explain with confidence
- the audience understand the business story without needing to decode the slides

---

# 1. Core Principle

The presentation must follow this rule:

> **Do not show data first. Show the story first, then use data as evidence.**

Every slide must answer one clear question.

The audience should always understand:

1. What problem exists?
2. Why does DevCraft exist?
3. How does the product work?
4. Who uses it?
5. Who creates value?
6. Who pays?
7. How does revenue happen?
8. What does it cost?
9. What remains as profit?
10. When does the business break even?
11. What can go wrong?
12. Why is the idea still worth testing?

# 22. Slide 15 — Fixed vs Variable Cost

Explain the concept before the numbers.

## Fixed Cost

> Costs we pay even if one additional user does not join.

Examples:

- base hosting
- tools
- marketing
- admin

### Simple analogy

**Like shop rent.**

---

## Variable Cost

> Costs that increase when platform usage or transactions increase.

Examples:

- payment fees
- extra bandwidth
- email/media
- transaction reserve

### Simple analogy

**Like ingredients used for each sale.**

## Presenter takeaway

> “Fixed cost supports the business. Variable cost grows with activity.”

# 26. Slide 19 — Break-Even

## Main question

How much monthly revenue does DevCraft need before it stops losing money?

## Formula

Break-Even Revenue  
= Fixed Cost ÷ Contribution Margin Ratio

## Calculation

`฿20,000 ÷ 0.949 ≈ ฿21,075`

Round:

## Visual

# 44. Codex Implementation Instruction

Do not rebuild the DevCraft product itself.

Update the existing presentation website.

Preserve the basic HTML/CSS/JS approach.

You may substantially restructure:

- HTML sections
- layout
- visual hierarchy
- CSS architecture
- financial presentation
- navigation
- animations

Do not preserve weak layouts only because they already exist.

The goal is clarity and storytelling, not minimal code changes.

When implementing:

1. rebuild the story structure first
2. then rebuild the visual system
3. then add charts and diagrams
4. then add motion
5. finally perform responsive and accessibility QA

Do not start by adding more decoration to the current card-heavy layout.
